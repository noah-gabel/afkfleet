# 0045. The script editor and a bot's script in the app: CodeMirror in a shadow root, one description, the app's own check, and the chat's ↑ and ↓

- **Status:** Accepted. Decided under ADR-0025. The user's additions to group F (errors while typing, the description's marks, hover help, the hooks' completion, the editing set, the error's link, the chat's ↑ and ↓) are the user's; how each is built is mine
- **Date:** 2026-11-21
- **Related:** Plan.md Phase 15, group F (P15.24 to P15.26, P15.35); [ADR-0036](0036-scripted-modes.md) (D4, D13, D15, D16), [ADR-0037](0037-scripts-read-system-chat.md) (C2, C5, C7), [ADR-0040](0040-fleet-script-as-built.md), [ADR-0042](0042-scripted-inputs-in-fleet-mc.md) (G13), [ADR-0044](0044-scripted-modes-on-the-wire-the-server-and-the-agent.md), whose decisions this builds; ADR-0017 (the CSP, no runtime styles, the IPC contract), ADR-0020 (U34: a line can hold a password; S60, S70: the live layer; S97, S107: the sweep); `packages/ui/src/features/scripts/`, `packages/ui/src/features/modes/scriptForm.ts`, `apps/desktop/src-tauri/src/script_check.rs`, `crates/fleet-api-types/src/script_api.rs`

## Context
Groups A to E built a scripted mode everywhere but in the app. Group F gives the app the editor ADR-0036's D16 chose, the mode editor's script body with its settings and declarations, and a bot's script on its page. The user added seven things to the group: errors while typing, checked by the app's Rust side with fleet-script; a method or property that doesn't exist marked from the API's description; hover help; `on_` offering each hook; CodeMirror's usual editing set, with Esc then Tab leaving the editor; a script's error on the bot's page linking to its line; and, in a bot's chat, ↑ and ↓ recalling the lines sent to it. Their reviewer named what they'd look at: the CSP unchanged, the constructed stylesheet allowed only inside the shadow root, the editor checked in the built app, a new Tauri command in every place frontend.md lists, the desktop crate's coverage, the app's size before and after Rhai, and every screenshot.

## Decisions

### F1. CodeMirror 6, picked package by package, in a shadow root
- **The packages,** each pinned exactly and at least 7 days old: `@codemirror/state` 6.7.6, `view` 6.43.15, `language` 6.13.1, `commands` 6.11.1, `autocomplete` 6.20.4, `lint` 6.9.8, `search` 6.7.2, and `@lezer/highlight` 1.2.5 for the highlighting's tags. **Not the `codemirror` package,** which ADR-0036 named: its `basicSetup` is a list of the same extensions, and `setup.ts` names each one instead. Their own dependencies come in through pnpm's 3-day rule: `style-mod` 4.1.5 (2026-11-17; it changes only how a selector is split and how a custom property is written, not where the styles go: the source diff), `@lezer/common` 1.5.5, `@lezer/lr` 1.4.12, `crelt` 1.0.7, `w3c-keyname` 2.2.8, `@marijn/find-cluster-break` 1.0.4.
- **The shadow root:** `ScriptEditor` attaches one to its host and mounts `new EditorView({ root, parent: root })`. style-mod then writes one constructed stylesheet for the document and adopts it into each editor's root (`StyleSet`, read in its source), which Edge's CSP allows; in the document it would write a `<style>`, which the CSP refuses. **The CSP is unchanged.**
- **frontend.md's one exception,** by name: the editor's shadow root (host `[data-slot="script-editor"]`) adopts that sheet. The Vitest guard (`styleGuard.ts`) and the e2e fixtures' guard both walk every open shadow root: no `<style>` in any, the editor's included, and an adopted sheet only in the editor's. jsdom has no `adoptedStyleSheets` on a shadow root, so style-mod would write a `<style>` there in tests; the Vitest setup gives jsdom Edge's accessor, so tests run the path the app runs.
- **The theme** (`theme.ts`) is the app's tokens only, through `var(--…)`, which crosses the shadow root. CodeMirror's packages bring base themes with colours of their own (gutters, selection, search panel, completion list, lint marks and tooltips, matched brackets, fold markers); every one is set again at the same weight and later. The lint marks are a wavy `text-decoration`, not lint's `data:` images. `scripts/theme-guard.mjs` holds it like any component.
- **The focus outline** is the host's: the one rule in `styles.css` gains `[data-slot="script-editor"]:focus-within`, since no rule in the document reaches into the root. The editor draws none of its own.
- **A fixed height, 26rem,** with the editor scrolling inside it, like a textarea. The sweep found why: a long script's host grew taller than the window, so part of its focus outline was out of sight. 26rem fits the 800×600 window.

### F2. A Rhai tokenizer of our own, one for everything
`rhai.ts` is a `StreamLanguage`: line and nested block comments, "…" strings (carried on by a backslash), `…` strings across lines with `${…}` inside, characters, Rhai's number forms, keywords, the game objects from the generated description, a member after a dot, a hook's name after `fn`, and a raw string's `#"` as invalid (the compiler refuses one, ADR-0040's A6). Indentation follows the brackets open at a line's start; folding is by a line that ends with `{`. **The same tokenizer** feeds `tokens()`, which the marks, the completion and the hover read, so what's coloured as a game object is what's checked as one.

### F3. One description, generated
`fleet_script::API`'s `Member` gains `object`: the API object a property is (`keys.forward` is an `input`), so a chain resolves. fleet-api-types depends on fleet-script now and turns `API`, `reasons()` and `EXAMPLES` into `ScriptApi`, which `just gen` writes as the constant `SCRIPT_API` in `packages/ui/src/generated/script-api.ts`, under a header of its own that `sync` treats as generated. **The completion, the marks, the hover and the starter templates read only that.** Each example is fleet-core's checked `Script` shown as an editor reads a mode (`ModeScript::of`), so a template fills the form exactly as a loaded mode does.
- **Found on Windows:** the file was first `scriptApi.ts`, which the file system took for `ScriptApi.ts` and wrote over. A test now holds that no two exported names differ only in case.
- **The cost:** fleet-client, which depends on fleet-api-types, compiles Rhai too, and links none of it. fleet-server and the desktop crate depend on fleet-script anyway.

### F4. The app's own check: `check_script`
- **What it is:** the desktop crate's command that compiles a script's text as the server does at save, and never runs it: fleet-api-types' `ModeScriptRequest::script` (fleet-core's rules for the text, with the default settings) and fleet-script's `compile`. **One wording:** the field error of a broken rule and of a text that isn't a program now live in fleet-api-types (`FieldError::from(ScriptFieldError)`, `not_a_program`), and the server's 422 uses the same two.
- **Off the UI's thread and the async runtime:** in `spawn_blocking`, one check at a time (a semaphore), waiting at most 5 s for the one before. It's no network call; compiling the longest script takes about a millisecond.
- **Untrusted text:** the text can be another Admin's shared script. A panic in the compiler is a `JoinError` (the release profile unwinds), and it and a wait past 5 s answer the new `CommandErrorCode::ScriptCheck`, which the editor shows as "Couldn't check the script", never a mark. The request is bounded at 64 KiB, four times a script's own limit, so a text past the limit is still told so by fleet-core's rule.
- **In every place frontend.md lists:** build.rs's `COMMANDS`, `generate_handler!`, `capabilities/main.json` (`allow-check-script`), `scripts/tauri-hardening.mjs`, `tests/ipc-contract.json` (and the ACL test's answer), `ApiClient` with `API_METHODS`, `TauriApiClient`, `FakeApiClient`, `UnavailableApiClient`, `validated.ts` (its zod schema, `SCRIPT_CHECK_MAX_BYTES` in `limits.ts`, which fleet-api-types' limits test holds), `watched.ts` (not watched: the app answers it, so it says nothing about the server) and the e2e fake's `COMMANDS` (a stand-in that marks a `kees`).
- **The editor's marks** come from one lint source, run after the typing pauses for 500 ms: the check's answer at its line and column (the engine counts a column in characters, CodeMirror in UTF-16 units: `places.ts`), the description's findings, and the server's 422 at `script.source` from the last save, until the text changes. The server stays the judge.

### F5. What the description finds that the compiler can't
`members.ts` walks each game object's chain: a member the object doesn't have (`keys.forwrd`, `mouse.left.hodl()`), a method without its parentheses, a value with them; and, with the form's declarations, a `chat.send` key no message has and a `chat.expect` key no reply pattern has. Each stops a script when its line runs (ADR-0036, D14; ADR-0040, E9), so each is a mark, but the save isn't blocked: the server would take it.

### F6. Completion, hover and the editing set
- **Completion:** after a game object's dot, its members, a method's parameters as fields to fill (`hold_for(${ms})`), a method's signature beside it and every member's summary; after `keys.forward.`, an input's; `on_` at a line's start or after `fn ` offers each hook with its parameters and an empty body (`fn on_join(first) { }`); any other name, the game objects. Nothing in a comment or a text. No icons: CodeMirror draws them with an opacity the sweep would read.
- **Hover:** a game object's summary, a member's signature written from its object (`keys.forward.hold_for(ms)`) and summary, a hook's definition. Its text is set as text.
- **The editing set** (`setup.ts`): line numbers, the active line, special characters, folding, undo and redo, bracket matching and closing, indentation on input, search and replace on top, several cursors (Ctrl+click, Alt+drag, Ctrl+D), the selection's matches. **Tab indents; Esc, then Tab, leaves:** CodeMirror lets Tab move the focus for two seconds after Esc. A hint under the editor says so, and the content's `aria-description` too, since ARIA's ids don't cross a shadow root.
- **Found by the e2e story, in Edge:** typing over a selection that spans highlighted tokens made Edge replace the DOM itself and add an inline-styled span, which the CSP refused (`style-src-attr`). `plaintext-only` alone didn't stop it. So a typed character over a selection, or at several cursors, goes through CodeMirror's own input handlers (closing brackets still wrap the selection) and never reaches the DOM, and a read-only text takes none; a plain cursor's typing stays the browser's, which input methods need. The content is `plaintext-only` too, which CodeMirror's base theme asks for through a property Chromium no longer reads.

### F7. The mode editor's script body (P15.25, P15.35)
- **Who chooses a script:** an Admin or the Owner, on a new mode (ADR-0036, D15). Everyone else's new mode is steps, a Member sees a shared script read-only, and only someone who writes scripts gets "Make a copy" of one. A mode's kind is set when it's made; turning steps into a script is group G's "Convert to script".
- **The sections:** the script in the editor, with the reference's four examples to start from on a new mode (a reset that keeps the loaded defaults, since the lists inside are field arrays); the leash, the tool guard and the blocks a held left button mines (G13); the declared messages with their typed values; the declared chat patterns with their captures, a pattern that may count at any time warned of as the riskier kind (C5). A mode's card and screen say "Runs: Script" and mark one that reads chat at any time.
- **The request** is built from the form alone (`scriptForm.ts`): each value and capture with its type's fields, an empty number left out for the server's message, every rule the server's (S82). The zod schema mirrors only what the wire carries. The 422's paths land on their fields, a whole value's rule on its smallest end, a one-line text's with the character it's at; `script.source` shows at its line in the editor.
- **`?line=&column=`** on a mode's route shows that place in its script.

### F8. A bot's script on its page (P15.26)
- **The Script card** shows where the script stands, what stopped or refused it, with its hook and its place, a link to that line of its mode, and its log, newest last. It shows for a bot on a scripted mode, and for any bot its script reported on.
- **Kept for the session, not only while the page is open:** the server stores none of it (ADR-0044, E10), and a status is said only at a change and at each join. So the live layer makes the one cache entry it ever makes, a bot's script record (a new patch kind, `keep`), with no expiry for the session; it holds the newest status and the last 200 log lines, a `bot_removed` resets it, and the session's end clears the cache with it.
- **D13, deferred by group E:** a scripted bot that qualifies while agents are live and none runs its mode's level reads `agent_too_old` (fleet-core's `shown`, from the mode's level and the registry's new `newest_script_api`); its page says "Waiting for an updated agent" and that an agent must be updated. With no agent live it waits as `awaiting_agent`, which is just as true.

### F9. The chat's ↑ and ↓ (the user's addition)
↑ fills in the last line the server took for that bot, ↑ again the one before, ↓ goes forward, and past the newest the box shows what was typed; typing ends browsing. A line can hold a password (ADR-0020, U34), so **the lines live in memory alone,** in a zustand store of the App (`stores.chatRecall`), never in the query cache or in storage: per bot, at most 50, the same line twice in a row once, dropped at sign-out, at a new sign-in, at the session's end, at a `bot_removed` and when the bot's read answers 404. Nothing is recalled while a send runs, while an input method composes, or with a modifier held. **The chat has had no password prompt since ADR-0028,** so the user's third condition holds by itself; a test of each of the other two was red with its guard taken out.

### F10. Checked in the built app, as P15.24 asks
`just app-build-check`, then `target/app-check/afkfleet-check.exe`, driven over WebView2's DevTools on loopback (WebView2 157), with the e2e fake answering every command inside the page but `check_script`, which reached the exe's own Rust side. Signed in, on a new scripted mode from the cobblestone example, with two lines typed: no CSP violation, no `<style>` in the document, no adopted sheet there and one in the editor's root, the editor laid out (`display: flex`), a keyword in `--primary`, the completion list after `keys.` on `--popover`, and two marks: `kees` from the real compiler ("Line 35, column 5: `kees` isn't defined") and `hodl` from the description. The screenshots matched Edge's. **WebView2 agrees with Edge, so ADR-0036's textarea fallback isn't needed.** The drive script was a throwaway outside the repository; the exe was stopped by its PID.

### F11. The sweep
The probe's text walk enters every open shadow root, and a backdrop and an opacity climb from a root's top to its host; the Tab walk presses Esc before Tab while the editor has the focus, the way out its hint gives. Three new rows (both themes, each its baselines): a new scripted mode from an example with its marks, a mode's messages with an any-time pattern, a bot's script stopped with its log. The server settings' rows change with the formats hint, which now also says a format keeps a script from reading a player's line (P15.34's deferral).

## Alternatives considered
- **The `codemirror` package's `basicSetup`.** The same extensions in a list we don't name; and its default highlight style, which we replace.
- **The description through a Tauri command,** answered by the Rust side at run time. The fakes and the e2e build would need a copy, which is a hand-written list.
- **The check in the UI, as WebAssembly.** A new toolchain and a second build of Rhai for one feature; the CSP has no `wasm-unsafe-eval`.
- **Checking only at save.** The user asked for errors while typing.
- **The recalled lines in `sessionStorage`.** Storage the user ruled out: a line can hold a password.
- **A textarea** (ADR-0036's fallback). Not needed: WebView2 agreed with Edge.

## Consequences
- **frontend.md has its one named exception,** held in both guards; the CSP is unchanged.
- **The desktop crate links fleet-script and Rhai,** and fleet-api-types depends on fleet-script.
- **A new command, `check_script`,** with its capability; **a new error code,** `script_check`; **a new waiting reason,** `agent_too_old`.
- **The live layer makes one entry of its own:** a bot's script record.
- **What's left for group G:** "Convert to script" (P15.27), the reference's tables from the same description and the records (P15.28), the phase's check (P15.29, P15.36).
